## 1. 大腸ポリープ時系列検証適応フレームワーク (Adaptive Temporal Validation Framework for Colorectal Polyp Detection - ステータス: 提案・計画中 — 未着手)
- カテゴリ: コンピュータビジョン | ディープラーニング | 医療 AI | 研究
- プロジェクト種別: 卒業研究提案（B.Tech 最終年）
- プロジェクトステータス: 提案・計画中（未着手）

### プロジェクト概要
大腸ポリープ時系列検証適応フレームワーク（Adaptive Temporal Validation Framework for Colorectal Polyp Detection）は、連続大腸内視鏡動画において、単一ビデオフレームにのみ依存するのではなく、時系列エビデンス（Temporal Evidence）を組み込むことで大腸ポリープ検出の信頼性と一貫性を向上させることを目的とした研究提案プロジェクトです。

### 大腸ポリープとは
大腸ポリープ（Colorectal Polyps）は大腸または直腸の内壁に発生する異常な組織増殖です。一部のポリープは時間の経過とともに大腸がんに進行するリスクがあるため、大腸内視鏡検査における正確な検出と評価が重要です。

### 課題定義
従来のコンピュータビジョンシステムは、適合率（Precision）、再現率（Recall）、mAP などの指標を用いて単一フレームレベルでポリープ検出を評価することが一般的です。しかし、フレーム単位の評価では、実際の連続大腸内視鏡動画における時系列的な挙動を捉えきれません。

連続内視鏡動画には以下の阻害要因が存在します：
- 急激なカメラ移動
- ポリープの一時的なオクルージョン（遮蔽）
- 組織の光反射および鏡面ハイライト
- モーションブラー（被写体ぶれ）
- ポリープの局所的な視認性
- 連続フレーム間での検出結果のちらつき（フリッカリング）
- バウンディングボックスの不安定性

これらの要因により、ポリープが存在している場合でも検出結果が不連続になる問題が発生します。

### 研究の動機
本プロジェクトは、連続するビデオフレーム間の時系列情報が、検出されたポリープの信頼性を判断するための強固な証拠を提供できるかを検証します。各フレームを独立して処理する代わりに、時間の経過に伴う検出の永続性および安定性を評価します。

### 提案目的
空間的検出結果、トラッキング情報、時系列永続性、バウンディングボックスの安定性、および動画運動特性を利用して、連続大腸内視鏡動画における大腸ポリープ検出の信頼性を評価する時系列検証フレームワークを開発すること。

### 提案システムのワークフロー
大腸ポリープ時系列検証適応フレームワークの処理パイプラインは以下のステップで連続内視鏡動画を処理します：
1. フレーム抽出 (Frame Extraction): 内視鏡動画ストリームからビデオフレームを時系列順に抽出。
2. ポリープ検出 (Polyp Detection): ディープラーニング検出器が抽出フレームを走査し、候補ポリープ領域を検出。
3. 物体トラッキング (Object Tracking): トラッカーが連続フレーム間で検出ポリープを追跡し、一定の空間 ID を維持。
4. 時系列エビデンス収集 (Temporal Evidence Collection): 座標、信頼度スコア、フレーム永続性データを蓄積。
5. 時系列一貫性検証 (Temporal Consistency Validation): バウンディングボックスの安定性、軌跡の一貫性、ジッターを検証。
6. 信頼性評価 (Reliability Assessment): 累積された時系列証拠から信頼性スコアを評価。
7. 適応的判定 (Confirm / Wait / Reject Decision): 検出結果を Confirm（確定）、Wait（待機）、または Reject（棄却）に分類。

### 提案検出レイヤー
単一フレーム内のポリープ位置特定のため、YOLO または RT-DETR などのリアルタイム物体検出モデルの検証を計画。
ステータス: 提案・計画中。

### 提案トラッキングレイヤー
連続フレーム間でのポリープ検出の対応付けと ID 維持のため、ByteTrack または DeepSORT の導入を計画。
ステータス: 提案・計画中。

### 時系列検証
時系列検証モジュールで評価する時系列要素：
- 連続フレームにおける検出継続性
- バウンディングボックスの安定性およびジッター
- 追跡軌跡の一貫性
- カメラ運動と動画の不連続性
- 一時的遮蔽、反射、ハイライト
- 時間経過による検出不変性

単一フレームの信頼度スコアのみではなく、フレームシーケンス全体の時系列信頼性を判断します。

### 提案判定レイヤー
- Confirm (確定): 十分な時系列証拠が検出を裏付けている。
- Wait (待機): 信頼できる判定を下すためにより多くのフレームが必要。
- Reject (棄却): 利用可能な時系列証拠が不十分または不整合。

### 提案セグメンテーション＆分類
セグメンテーション用に SAM 2 や U-Net++、病理分類用に EfficientNet などの検討を計画。
ステータス: 提案・計画中。

### 説明可能性
予測根拠領域を視覚化するため Grad-CAM などの XAI 手法の導入を計画。
ステータス: 提案・計画中。

### 提案LLMレポート生成
検出ポリープ数、位置、サイズ、分類、信頼度スコアから構造化大腸内視鏡検査レポートを自動生成する LLM モジュールの検討を計画。レポート作成目的であり独立診断用ではありません。
ステータス: 提案・計画中。

### 期待される研究成果
連続内視鏡動画における時系列信頼性を評価し、フレームレベル指標を補完する時系列証拠の効用を検証します。

### 提案技術
- Python
- Computer Vision
- Deep Learning
- Object Detection
- Object Tracking
- Image Segmentation
- Temporal Analysis
- Video Processing
- Explainable AI
- Large Language Models

### 現在のステータス
本プロジェクトは**提案・計画中の B.Tech 最終年卒業研究であり、現在実装・開始されていません**。実験評価データや臨床検証データは存在しません。

### 限界と今後の展望
データセット選定、モデル実装、時系列検証実験、定量的評価、比較実験を計画。臨床検証および実デプロイは医療評価が必要なため現在の提案範囲外です。

## 2. GeoSentinel — AI搭載土砂崩れ検出システム (GeoSentinel — AI-Powered Landslide Detection System)

- カテゴリ: 人工知能 | コンピュータビジョン | ディープラーニング | 防災管理
- プロジェクト種別: リアルタイム土砂崩れ検出およびモニタリングシステム
- GitHub リポジトリ: https://github.com/Sujan-lab-cell/GeoSentinel-Landslide-Detection-System.git

### プロジェクト概要
GeoSentinel は、衛星画像、航空写真、およびドローン撮影動画から土砂崩れ地域を自動検出しモニタリングする AI 搭載の地理空間分析システムです。YOLOv8-Seg インスタンスセグメンテーションモデルを用いて土砂崩れ領域を精密に抽出・境界特定し、地理空間視覚化、リスク分類、自動アラート発報、動画解析、および過去履歴のモニタリング機能を統合しています。

### 目的
- ディープラーニングベースのインスタンスセグメンテーションを用いた土砂崩れ地域の検出。
- 検出信頼度およびリスクレベル分類の提供。
- ドローン動画のフレームごとの土砂崩れ検出解析。
- インタラクティブマップを使用した検出位置の可視化。
- 土砂崩れ検出時の自動 SMS および Email アラート送信。
- 過去の検出記録の保持と土砂崩れヒートマップの生成。

### データセット
GeoSentinel モデルは、公開データ源および衛星画像ソースから集約されたカスタム土砂崩れセグメンテーションデータセットを用いて訓練されました。
- アノテーション済み総画像数: GeoSentinel データセットには合計 821 枚のアノテーション済み画像が含まれます。
- 訓練用画像数: 711 枚
- 検証用画像数: 70 枚
- テスト用画像数: 40 枚
- 初期収集未加工画像数: 327 枚
- クラス名: `landslide`
- アノテーション形式: YOLO 形式のポリゴンセグメンテーションマスク。
データソースには Roboflow、Kaggle Landslide4Sense、および NASA Landslide Inventory が含まれます。

### 前処理とデータ拡張
- 画像方向の自動補正。
- 640 × 640 ピクセルへのリサイズ。
- 水平反転。
- -5° から +5° のランダム回転。
- -20% から +20% の輝度変動。
- 最大 1.5 px のブラー拡張。
- ピクセルの最大 1.33% に対するノード拡張。

### モデルアーキテクチャ
GeoSentinel は Ultralytics の **YOLOv8-Seg**（YOLOv8 のセグメンテーション変種）を使用しています。

### モデル設定
- 学習済みモデル: `yolov8n-seg.pt`
- 入力サイズ: 640 × 640
- タスク: Instance Segmentation
- クラス数: 1 (`landslide`)
- 信頼度閾値 (Confidence threshold): 0.50
- オプティマイザ: AdamW
- エポック数: 100
- バッチサイズ: 16
- 初期学習率: 0.01
- 最終学習率: 0.0001

### モデル性能
- ボックス精度 (Bounding-Box Precision): GeoSentinel の YOLOv8-Seg モデルは Bounding-Box Precision で 0.892 を達成しました。
- ボックス再現率 (Bounding-Box Recall): GeoSentinel の YOLOv8-Seg モデルは Bounding-Box Recall で 0.854 を達成しました。
- ボックス mAP@50: GeoSentinel の YOLOv8-Seg モデルは Bounding-Box mAP@50 で 0.887 を達成しました。
- マスク精度 (Mask Precision): GeoSentinel の YOLOv8-Seg モデルは Mask Precision で 0.875 を達成しました。
- マスク再現率 (Mask Recall): GeoSentinel の YOLOv8-Seg モデルは Mask Recall で 0.838 を達成しました。
- マスク mAP@50: GeoSentinel の YOLOv8-Seg モデルは Mask mAP@50 で 0.864 を達成しました。

### データセットバイアスおよび偽陽性
- 主な偽陽性要因: 裸地、大規模採石場、未舗装の道路、および農地の開墾地域。
- 対策: 地形傾斜データおよび植生指数（NDVI）を判定フィルタとして追加統合。

### 混同行列の観察結果
- 侵食が進行している山岳地帯において非常に高いセグメンテーション精度を記録。
- 雲の影や極端な逆光条件下では軽微な境界判定精度の低下が観察されました。

### アプリケーションワークフロー
GeoSentinel のシステムワークフロー：
1. 画像・動画データのアップロード
2. YOLOv8-Seg によるセグメンテーション推論の実行
3. 検出ポリゴンの地理座標変換および面積計算
4. リスクレベルの自動判定（High / Medium / Low）
5. インタラクティブマップ上への描画およびアラート通知の発報

### 画像解析
- 静止画像（衛星写真・ドローン撮影）を入力とし、数秒以内に土砂崩れ領域のポリゴンマスクと被害推計面積を出力。

### ドローン動画解析
- ドローンで撮影された連続動画フレームをリアルタイムで解析し、移動に伴う土砂崩れ領域の追跡と変化検知を実施。

### 地理的マッピング
- Folium / Leaflet を統合し、検出された土砂崩れポリゴンを衛生地図上に正確にプロット。

### 自動アラート
- 高リスク（High Risk）の土砂崩れが検出された場合、管理者に即座に通知を送信するアラート機能を搭載。

### 履歴モニタリング
- 同一地域の時系列データをデータベースに蓄積し、時間の経過に伴う地すべり領域の拡大・推移を比較・視覚化。

### リスク分類
- 被害面積、傾斜角度、および周辺の建造物密度に基づき、リスクレベルを「High」「Medium」「Low」の3段階に自動分類。

### 技術スタック
- 言語: Python 3.10+
- AI / Deep Learning: PyTorch, Ultralytics YOLOv8-Seg, OpenCV, Roboflow
- 地理情報・視覚化: Folium, GeoPandas, Streamlit, Matplotlib
- バックエンド・インフラ: FastAPI, Docker, Render

### 主な機能
- セグメンテーションマスクによる土砂崩れ領域の精密描画
- ドローン動画のリアルタイムフレーム解析
- 地理空間マッピングおよびリスク自動判定
- 履歴データの保存と時系列変化のモニタリング

### 実世界のユースケース
- 防災機関、自治体、および緊急救助チームが、土砂災害の迅速な状況把握と二次災害の防止に活用。

### 主な課題と対策
- 複雑な自然地形における誤検知を低減するため、データ拡張の強化とバックボーンモデルの調整を実施。

### プロジェクト成果
- 高精度な土砂崩れ検出・自動マッピングシステムを構築し、プロトタイプ Web アプリケーションとして動作実証を完了。

### 今後の展望
- 降雨量リアルタイムデータ API や標高デジタルモデル（DEM）との直接連携による予測精度のさらなる向上。

## 3. SmartQ Generator — 多言語問題自動生成システム (SmartQ Generator — Multilingual Question Generation System)

- カテゴリ: 自然言語処理 (NLP) | 機械学習 | 教育テクノロジー
- プロジェクト種別: 自動問題生成＆難易度評価 Web アプリケーション
- GitHub リポジトリ: https://github.com/Sujan-lab-cell/SmartQ-Generator.git

### プロジェクト概要
SmartQ Generator は、入力テキストから多言語の質問・解答ペアを自動生成し、難易度判定および音声合成（TTS）を提供する自然言語処理（NLP）Web アプリケーションです。Hugging Face の Transformer モデル（T5）を活用し、教育機関や学習者の問題作成作業を大幅に効率化します。

### 主な目的
- 長文テキストからの多言語問題（択一式、短答式、正誤問題等）および解答の自動生成。
- 難易度（Easy, Medium, Hard）の自動スコアリングと分類。
- 生成されたテキストの音声朗読（Text-to-Speech）および多様なファイル形式（PDF, TXT）への出力。

### 入力方法
SmartQ Generator でサポートされている入力方法：
- 直接テキスト入力
- ドキュメントファイルのアップロード (.txt, .pdf, .docx)
- URL からの Web 記事テキスト自動抽出

### 主な処理パイプライン
SmartQ Generator のメイン処理パイプライン：
1. 入力テキストの受信とテキスト前処理（文分割・トークン化）
2. 重要な文脈および重要語句の自動抽出
3. T5 Transformer モデルによる質問・解答ペアの生成
4. 難易度スコアリングエンジンによる評価
5. ユーザー編集インターフェースへの表示およびファイル出力

### 多言語処理
- 英語、日本語、およびその他の主要言語に対応。言語検出ライブラリにより入力テキストの言語を自動認識。

### 質問生成

### 4. WGAN-GPを用いたAI人体顔画像生成 (AI Human Face Generation using WGAN-GP)

- カテゴリ: ディープラーニング | 生成 AI | コンピュータビジョン
- プロジェクト種別: 研究・実験的画像生成システム
- GitHub リポジトリ: https://github.com/Sujan-lab-cell/AI-Human-Face-Generation-using-WGAN-GP.git

### プロジェクト概要
WGAN-GPを用いたAI人体顔画像生成（AI Human Face Generation using WGAN-GP）は、勾配ペナルティ付き Wasserstein GAN (WGAN-GP) アーキテクチャを用いて、高解像度かつリアルな人体顔画像を合成するディープラーニングモデルの研究・開発プロジェクトです。従来の GAN におけるモード崩壊（Mode Collapse）や勾配消失問題を克服し、安定したモデル学習を実現しました。

### 目的
- WGAN-GP アーキテクチャの設計および実装。
- 人体顔画像データセットにおける学習の安定化と生成品質の向上。
- Inception Score (IS) を用いた生成画像の定量的品質評価。

### データセット
- データセット名: CelebA (CelebFaces Attributes Dataset) / カスタム顔画像データセット。
- 画像枚数: 200,000 枚以上の有名人顔画像。

### 顔検出・クロップおよび前処理
- Haar Cascade または MTCNN を用いて顔領域を自動検出し、正方形領域にトリミング。
- 解像度のリサイズ (64x64 および 128x128) とピクセル値の正規化 ([-1, 1])。

### データ拡張
- ランダム水平反転、軽微な色調変動、および回転適用によるデータの多様化。

### WGAN-GP アーキテクチャ
### 判別器 / 評価器 (Critic)
- バッチノーマライゼーションを除外し、レイヤーノーマライゼーション（Layer Normalization）を採用。
- 観測画像と生成画像の中間点における勾配のノルムに対するペナルティ項（Gradient Penalty）を損失関数に追加。
### 生成器 (Generator)
- 転置コンボリューション（Transposed Convolution）層、バッチノーマライゼーション、および ReLU/Tanh 活性化関数で構成。

### アーキテクチャ実験
### 実験 1 — 128x128 高解像度生成
- 高解像度生成を目指したモデル構成。細部の描写力は向上するものの、より多くの計算リソースと学習時間を要しました。
### 実験 2 — 64x64 安定学習生成
- 学習速度と生成品質のバランスに優れ、非常に安定した損失収束を確認。

### アーキテクチャ比較
- 標準 DCGAN と比較して、WGAN-GP は学習初期からの損失関数の滑らかな減少と優れた画像品質を示しました。

### 訓練設定
WGAN-GP モデルの訓練ハイパーパラメータ：
- オプティマイザ: Adam ($eta_1 = 0.5, eta_2 = 0.9$)
- 学習率: Generator = 0.0001, Critic = 0.0001
- Gradient Penalty 係数 ($\lambda$): 10
- Critic 更新回数 ($n_{	ext{critic}}$): Generator 1 回の更新につき Critic 5 回更新

### 訓練の安定性
- Critic の損失値が生成画像のクオリティと直接相関するため、学習進行のモニタリングが容易化されました。

### モード崩壊の解析
- 勾配ペナルティの導入により、生成器が単一のパターンのみを出力するモード崩壊を完全に防止。

### Inception Score 評価
- 評価指標: Inception Score (IS)
- WGAN-GP モデルの評価では、従来モデルと比較して有意に高い Inception Score を達成し、多様で明瞭な顔画像生成を確認しました。

### 発生した課題
- 学習初期における生成画像のノイズ化、Critic が強くなりすぎる不均衡、チェックポイント管理の錯綜、および部分的な輪郭のぼやけ。

### 解決策
- 勾配ペナルティ ($\lambda = 10$) の厳密適用、顔領域の正確なトリミング、オプティマイザハイパーパラメータの再調整、および評価指標による定期検証。

### 主な機能
- 高度な WGAN-GP 損失関数による安定学習
- ノイズベクトルからのリアルな人工顔画像リアルタイム生成
- 品質評価ツールの統合

### 技術スタック
- 言語・フレームワーク: Python, PyTorch, torchvision, OpenCV, NumPy, Matplotlib, CUDA

### プロジェクト成果
- モード崩壊を起こさずに高品質な人造顔画像を安定生成する生成 AI モデルの構築に成功。

### 今後の改善点
- StyleGAN アーキテクチャの導入による 512x512 / 1024x1024 超高解像度画像の生成および潜在空間属性編集機能の追加。

## 6. FlyRank AI インターンシップ — 機械学習エンジニアリング＆検索ランキング予測 (FlyRank AI Internship — ML Engineering)

- 企業: FlyRank.ai / FlyRank AI
- 期間: 2026年7月1日 – 2026年9月9日
- 成果: 5,000 件の URL データセットにおける Google 検索順位下落予測モデルの構築。
- GitHub リポジトリ: https://github.com/Sujan-lab-cell

## 1. インターンシップ概要
FlyRank.ai にて、検索インデックスの変更やアルゴリズムの更新前に Google 検索ランキングの大幅な下落を予測する研究・実用レベルの機械学習モデルを設計・開発しました。本取り組みは、検索アナリティクス、時系列特徴量抽出、データリーク防止手法、および評価指標に関する査読済み研究論文として論文出版が準備されています。

## 2. 主要インターンシップ目的
目的は、2024年5月の Google アルゴリズム更新前後のデータを活用し、将来的に検索表示順位が低下するリスクの高い URL を事前に予兆検知することです。

## 3. Google検索ランキング＆発見可能性の取り組み
検索トラフィックデータの時系列分析、特徴量設計、および評価ベンチマークの策定を実施しました。

## 4. データセット
- 全体集計母集団: 5,000 件の追跡 URL。
- モデル適用母集団: 観測期間中に最低 100 インプレッション以上を有する検証済み URL。

## 5. タイムウィンドウ
- 特徴量計算期間 (Pre-May 2024): 2024年5月以前の履歴データ。
- ターゲット評価期間 (Post-May 2024): 2024年5月更新後のトラフィック変化。

## 6. ターゲット定義
- 下落（Decline = 1）: 更新後に表示順位またはクリック数が著しく減少したページ。
- 非下落（Non-Decline = 0）: 順位が維持または向上したページ。

## 7. 適格基準
ノイズページや新規作成ページを除外するためのプレフィルタリング（Pre-May インプレッション 100 以上）。

## 8. 特徴量エンジニアリング
9 つの Pre-May 予測特徴量:
1. `pre_may_clicks`: 更新前の総クリック数。
2. `pre_may_impressions`: 更新前の総インプレッション数。
3. `pre_may_ctr`: 事前クリック率（Clicks / Impressions）。
4. `pre_may_position`: 平均 SERP 表示順位。
5. `click_share`: 総トラフィックに対する当該 URL のクリックシェア。
6. `impression_share`: 総インプレッションに対する表示シェア。
7. `ctr_diff`: 期待 CTR と実際の CTR の乖離度。
8. `pos_ctr_ratio`: 平均表示順位と CTR の比率。
9. `click_per_pos`: 表示順位 1 単位あたりの獲得クリック数。

## 9. リーク防止
特徴量計算時に Post-May のデータを完全に排除し、厳格な時系列分離を徹底。

### 10. ベースライン手法
Pre-May CTR に基づく単純ソートルールにおける評価では、Precision@50 は 0.392 でした。

### 11. 試験された機械学習モデル
- ロジスティック回帰 (Logistic Regression): Precision@50 = 0.408
- 決定木 (Decision Tree): Precision@50 = 0.418
- ランダムフォレスト (Random Forest - 最終モデル): Precision@50 = 0.444

### 12. モデル比較
ランダムフォレストがすべての評価指標において最高の性能を発揮しました。

### 13. 最終ランダムフォレストモデル
- パラメータ: `n_estimators=200`, `max_depth=8`, `min_samples_split=5`, `random_state=42`
- 最終 Precision@50: **0.444**

### 14. ベースラインに対する改善
FlyRank ML インターンシッププロジェクトにおいて、ベースライン (Precision@50 = 0.392) に対し、最終ランダムフォレストモデルは Precision@50 で 0.444 を達成しました (+13.3% 相対向上)。

### 15. ランダムフォレスト特徴量重要度

- `pre_may_ctr`: **21.2%**

### 7. Eコマース売上ダッシュボード (Power BI) (E-commerce Sales Dashboard - Power BI)

- カテゴリ: ビジネスインテリジェンス | データ分析 | BI ダッシュボード
- プロジェクト種別: インタラクティブ Power BI 売上・収益性分析ダッシュボード
- GitHub リポジトリ: https://github.com/Sujan-lab-cell/E-Commerce-Sales-Dashboard.git

### プロジェクト概要
Eコマース売上ダッシュボード (Power BI) は、オンラインストアの注文・売上データを分析・可視化するために作成された Power BI ビジネスインテリジェンス（BI）ダッシュボードです。売上高、利益、注文数量、顧客獲得コスト、および地域別パフォーマンスなどの主要業績評価指標（KPI）をインタラクティブに分析できます。

### 目的
- オンライン注文データからのビジネスインサイトの抽出。
- DAX (Data Analysis Expressions) を用いたアドホック指標の動的計算。
- 地域、カテゴリ、支払い方法別の収益性の可視化。

### データセット
- Orders テーブル: 注文 ID、注文日、顧客名、国/地域、州、都市。
- Details テーブル: 注文 ID、売上金額、利益、数量、カテゴリ、サブカテゴリ、支払い方法。

### 主要業績評価指標
- 総売上高 (Total Sales)
- 総利益 (Total Profit)
- 総注文数量 (Total Quantity)
- 利益率 (Profit Margin %)
- 平均注文数値 (Average Order Value - AOV)

### DAX 計算式
Power BI ダッシュボードで使用された主要な DAX 計算式：
- Total Sales = SUM(Details[Amount])
- Total Profit = SUM(Details[Profit])
- Total Quantity = SUM(Details[Quantity])
- Profit Margin % = DIVIDE([Total Profit], [Total Sales], 0)
- Average Order Value = DIVIDE([Total Sales], DISTINCTCOUNT(Orders[Order ID]), 0)
- Profit per Order = DIVIDE([Total Profit], DISTINCTCOUNT(Orders[Order ID]), 0)
- Sales per Unit = DIVIDE([Total Sales], [Total Quantity], 0)
- Profit Category = IF([Total Profit] > 0, "Profitable", "Loss-making")

### ダッシュボードフィルター
- 注文日付（年・月・四半期スライサー）
- 地域・州スライサー
- 製品カテゴリ・サブカテゴリ
- 支払い方法（クレジットカード、UPI、代金引換等）

### 可視化要素
- KPI カード表示
- 月別売上・利益トレンドライン

## 10. RAG 駆動ポートフォリオ AI アシスタント (RAG-Powered Portfolio AI Assistant)

### プロジェクト概要
ポートフォリオウェブサイト訪問者が、スジャンの経歴、教育、技術スキル、プロジェクト、インターンシップ、実績、および技術経験について自然言語で質問できる AI 駆動会話型アシスタントを開発・構築しました。

アシスタントは検索拡張生成 (RAG: Retrieval-Augmented Generation) を利用し、グラウンディングされた回答を生成する前に、構造化された Markdown ナレッジベースから関連するポートフォリオ情報を検索します。

また、本システムは短期会話メモリと軽量な会話型参照リゾルバーをサポートしており、追質問において前のコンテキスト（「it」「this project」「there」など）を理解して検索クエリを適切に補正・解決します。

- カテゴリ: 人工知能 | 生成AI | 自然言語処理 (NLP) | RAG | LLM
- プロジェクト種別: 会話型検索拡張生成 (RAG) システム
- GitHub リポジトリ: https://github.com/Sujan-lab-cell/Port_Folio.git

### アーキテクチャ
エンドツーエンドの技術アーキテクチャは以下の処理パイプラインに従います：

ユーザー質問 → 短期会話履歴 → ナレッジ・ナビゲーション意図検出 → 会話型参照解決 (リゾルバー) → BGE-M3 多言語埋め込み (Vector Embedding) → Supabase ベクトル検索 (pgvector) → ハイブリッド検索 / 再ランキング (Reranking) → コンテキスト組み立て → Grok LLM → グラウンディング回答生成

### ナレッジベース (Knowledge Base)
ポートフォリオナレッジは、英語 (`knowledge/en/`) および日本語 (`knowledge/ja/`) の分離されたディレクトリ構造で構造化 Markdown ファイルとして維持管理されています。

ナレッジ領域に含まれる情報：
- プロフィール & 略歴
- 学歴・教育
- 技術スキル
- プロジェクトポートフォリオ
- 職務経験 & インターンシップ
- 資格認定 & 受賞実績
- 履歴書・職務経歴書 (英語版および日本語版)

### 埋め込みモデル (Embedding Model)
- モデル: BAAI/bge-m3
- フレームワーク: Sentence Transformers & Python 埋め込みサービス
- 目的: 英語および日本語テキストにわたり、ポートフォリオナレッジの Markdown チャンクおよびユーザー質問を高次元高密度ベクトルに変換し、セマンティック検索を可能にします。

### ベクトル検索 (Vector Search)
- ベクトルデータベース: Supabase (pgvector)
- パイプライン構成要素:
  - Markdown ナレッジの取り込み
  - ドキュメントのチャンク分割
  - BGE-M3 密ベクトル生成
  - Supabase ベクトル類似度検索
  - ハイブリッド検索 (Hybrid Retrieval)
  - 相互順位融合 (RRF) 再ランキング (Reranking)
  - コンテキスト組み立て
  - グラウンディング LLM 回答生成

### 会話メモリ (Conversational Memory)
アシスタントは、直近最大 6 つのユーザーおよびアシスタントのメッセージを `/api/chat` エンドポイントに送信することで、短期会話履歴を保持します。これにより、永続的なユーザーセッションデータベースを必要とせずに、直前の対話ターンを利用して追質問をコンテキスト化できます。

### 参照解決 (Reference Resolution)
軽量なローカルリゾルバーにより、すべてのターンで高コストな LLM 呼び出しを行うことなく、追質問における会話参照を解決します。

サポート対象の参照解決用語：
- 「it」(それ / そのプロジェクト)
- 「this project」(このプロジェクト)
- 「that project」(そのプロジェクト)
- 「there」(そこで / その企業で)

リゾルバーは、決定論的な最新性ルール (Recency Rules) を用いて、会話履歴から最も最近の互換性のあるエンティティに参照をマッピングします。

重要な解決ルール：
1. **明示的エンティティ優先 (Explicit Entity Priority):** 現在の質問に含まれる明示的なエンティティ名は会話履歴より優先されます（例: 履歴に SmartQ Generator が含まれていても「GeoSentinel で使用された技術は何ですか？」と質問された場合、GeoSentinel が維持されます）。
2. **単数参照の解決 (Singular Reference Resolution):** 単数参照 (「it」「this project」「that project」「there」) は、コンテキスト内の最も最近の互換エンティティに解決されます。
3. **複数参照の安全性 (Plural Reference Safety):** 複数参照 (「them」「these」「those」) は単一エンティティに折りたたまれず、安全に保存されます。
4. **コンテキスト不在時の安全性 (No-Context Safety):** 会話コンテキストや一致するエンティティがない質問は書き換えられず、誤ったエンティティの置換を防止します。

### ナビゲーション意図検出 (Navigation Intent)
アシスタントには、ユーザーのページ移動要求（「プロジェクトを見せて」「経歴ページを開いて」「スキルを表示して」など）を識別する意図検出レイヤーが含まれています。検出された場合、システムは直ちに構造化されたナビゲーションルーティングアクション (`navAction`) を返し、要求されたポートフォリオページにユーザーを誘導します。

### デプロイフォールバック (Deployment Fallback)
アシスタントは、環境変数 (`AI_ASSISTANT_MODE`) で制御されるデュアル動作モードをサポートします：
- `AI_ASSISTANT_MODE=rag`: 完全なローカル RAG パイプライン (BGE-M3 + Supabase + Grok) を使用します。
- `AI_ASSISTANT_MODE=rule`: ローカル Python 埋め込みサービスやベクトルデータベースが利用できないサーバーレス環境 (Vercel など) 向けに、構造化ナレッジと決定論的解決を用いた軽量かつデプロイ安全なルールフォールバックを提供します。ルールモードは BGE-M3、Supabase、Grok、Python サービスを呼び出さずに独立して動作します。
